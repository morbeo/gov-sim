# bgfin

Collects Bulgarian economic and financial indicators from official sources into PostgreSQL, keeps every
published version of every value, and shows them in Grafana with alerts.

- Sources: Eurostat, ECB, IMF, World Bank, BIS, European Commission AMECO, NSI (BNB: see
  [docs/source-inventory.md](docs/source-inventory.md)).
- Indicators: [docs/indicator-catalogue.md](docs/indicator-catalogue.md), defined in `config/indicators.yaml`.
- Nothing is overwritten: a revised value supersedes the old row, which stays queryable.

## Install (Linux server with Docker)

```sh
git clone https://github.com/morbeo/gov-sim && cd gov-sim/bgfin
cp .env.example .env            # set the three passwords
docker compose up -d            # PostgreSQL, collector, Grafana
docker compose run --rm collector backfill    # first full history load, about a minute
```

Grafana: http://localhost:3000 (light theme, admin password from `.env`). Both ports bind to
127.0.0.1; use an SSH tunnel or a reverse proxy with TLS for remote access.

The collector container runs `bgfin run`: every 15 minutes it collects each source whose
`interval_hours` has passed, then recomputes derived metrics and runs validation.

### Without Docker

```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -e .
export BGFIN_DSN=postgresql://bgfin:secret@localhost:5432/bgfin
bgfin init && bgfin backfill
bgfin run                       # or `bgfin run --once` from cron / a systemd timer
```

## Everyday commands

| Command | What it does |
|---|---|
| `bgfin status` | Last run per source, series counts, stale series, open issues |
| `bgfin collect` | Incremental update of all sources (full refresh when `full_refresh_days` is due) |
| `bgfin collect eurostat -i hicp_inflation` | One source, one indicator |
| `bgfin backfill [SOURCE...]` | Re-read full history (safe to repeat: unchanged values are not rewritten) |
| `bgfin collect --dry-run` | Fetch and parse without writing |
| `bgfin derive` / `bgfin validate` | Recompute derived metrics / run data checks |
| `bgfin issues` / `bgfin issues --resolve 12 13` | Review data-quality findings |
| `bgfin as-of 2026-11-01T00:00Z hicp_inflation` | The indicator as the database knew it at that time |
| `bgfin catalogue` | Regenerate docs/indicator-catalogue.md |

In Docker prefix with `docker compose run --rm collector`, e.g. `docker compose run --rm collector status`.
Add `--json` for machine-readable output. Exit code is 1 when a source fails, 2 on config or connection errors.

## How data is stored

Schema `bgfin` (SQL in `src/bgfin/sql/`, applied by `bgfin init`):

- `source`, `indicator`, `series` (one row per source series: dataset, key, geography, unit, frequency,
  seasonal adjustment, role).
- `observation`: one row per retrieved version. `revision` 0 is the first value seen; a changed value,
  status flag or type (e.g. provisional to final) sets `superseded_at` on the old row and adds `revision + 1`.
  Forecasts carry a `vintage` (`WEO-2026-10`, `AMECO-2026-11`), so forecast rounds coexist.
  `obs_type` is one of actual, preliminary, estimate, forecast, missing; `status` keeps the source's own flag.
- `derived_observation`: computed metrics with their formula and the ids of the raw values used.
- `collection_run`, `dataset_state`: run log, errors, conditional-request state.
- `quality_issue`: stale series, outlier changes, large revisions, vanished values, source failures.
- `alert_threshold`: loaded from `config/alerts.yaml`.

Useful views: `v_obs_current`, `v_indicator_values` (raw + derived), `v_changes` (period and year changes),
`v_revisions`, `v_first_vs_latest`, `v_forecast_vs_actual`, `v_forecast_revisions`, `v_freshness`,
`v_source_health`, `v_threshold_status`; function `obs_as_of(timestamp)`.

## Dashboards and alerts

Dashboards are generated by `grafana/build_dashboards.py` (edit it, run it, Grafana reloads within a minute):

- **Overview**: latest Bulgarian values, history against EA21 and EU27, threshold status.
- **Indicator explorer**: any indicator, source and geography; changes and revisions.
- **Bulgaria vs EU and peers**: RO, HR, GR, HU, PL, CZ, SK, SI, EU27, EA21.
- **Forecasts vs actuals**: IMF and Commission forecasts by vintage, errors, revisions between rounds.
- **Data health**: source runs, freshness, quality issues, recent revisions.

Alert rules (`grafana/provisioning/alerting/bgfin-rules.yaml`): indicator threshold breached, source run
failed, source overdue, stale Bulgarian series, new anomalies. Thresholds themselves are in
`config/alerts.yaml`; run `bgfin sync-config` (or any collect) after editing. Set up where notifications go in
Grafana under Alerting > Contact points.

## Extending

**Add a series to an existing source**: add an entry under the indicator's `series:` in
`config/indicators.yaml` (see the field list at the top of that file), then `bgfin backfill SOURCE -i CODE`.
For Eurostat, filters must pin every dimension except `geo` and `time`; the collector reports which
dimension is ambiguous otherwise.

**Add an indicator**: new block in `config/indicators.yaml` with `code`, `name`, `category`, `unit`,
`frequency` and `series`. Run `bgfin catalogue` to update the docs.

**Add a derived metric**: add a function to `src/bgfin/derive.py` (`FUNCTIONS`) and an entry in
`config/derived.yaml`. Derived values are versioned like raw ones and keep their inputs.

**Add a source**: subclass `Connector` in `src/bgfin/connectors/` with a `fetch(specs, mode)` generator
that yields `(spec, SeriesData)`; register it in `connectors/__init__.py` and add it to
`config/sources.yaml`. SDMX providers can reuse `SdmxConnector` (see `bis.py`, 10 lines).

## Notes on Bulgaria's euro adoption (1 January 2026)

- ECB BSI/MIR data for Bulgaria starts in January 2023; the BGN/EUR rate series ends 2025-12-31.
- AMECO and Eurostat show national-currency history converted at 1.95583 BGN per EUR.
- Eurostat's euro-area comparison aggregate is EA21; ECB series use U2 (changing composition), stored as `EA`.
- HICP moved to ECOICOP v2 in 2026 (`prc_hicp_minr`), independent of euro adoption.
